# نظام إدارة إجازات البناء — Flutter + Supabase + Hive

تطبيق مؤسسي (موبايل + ويندوز) لإدارة إجازات البناء بمزامنة لحظية بين كل الأجهزة،
يعمل بدون إنترنت (Offline-First) ويُزامن تلقائياً فور عودة الاتصال.

---

## 1) هيكل المشروع

```
building_permits_app/

│   ├── main.dart                 نقطة التشغيل
│   ├── app.dart                  MaterialApp + الثيم + اللغة
```

## 2) خطوات الإعداد (بالترتيب)

### أ) إنشاء مشروع Supabase
1. أنشئ حساباً/مشروعاً في https://supabase.com (خطة Free تكفي للبدء، ثم Pro بـ25$ شهرياً عند الحاجة كما ذكرت).
2. من **SQL Editor**، افتح ملف `supabase/schema.sql` من هذا المشروع، وشغّله بالكامل.
   هذا ينشئ: الجداول، سياسات الأمان RLS، المزامنة اللحظية Realtime، سجل التدقيق، وحاوية تخزين المرفقات.
3. من **Project Settings > API**، انسخ:
   - `Project URL`
   - `anon public key`
4. افتح `lib/core/constants/app_constants.dart` وضع القيمتين مكان:
   ```dart
   static const String supabaseUrl = 'https://YOUR_PROJECT_REF.supabase.co';
   static const String supabaseAnonKey = 'YOUR_SUPABASE_ANON_KEY';
   ```

### ب) إنشاء أول حساب أدمن
1. من **Authentication > Users** في Supabase Dashboard، أضف مستخدماً (بريد + كلمة مرور).
2. من **SQL Editor** نفّذ (استبدل القيم):
   ```sql
   insert into public.profiles (id, full_name, role, is_active)
   values ('USER_UUID_FROM_AUTH', 'اسمك الكامل', 'admin', true);
   ```
   (يمكن أخذ `USER_UUID` من صفحة Authentication > Users بعد إنشاء الحساب)
3. لإضافة باقي الموظفين لاحقاً: أنشئ حساباتهم من Authentication > Users، ثم يدخل الأدمن على
   شاشة **إدارة المستخدمين** داخل التطبيق ليضبط الدور (موظف/أدمن) والتفعيل — لا حاجة لأي SQL يدوي بعد ذلك.

### ج) ترحيل بياناتك القديمة (6169 سجل من ملفيك)
تم اختبار السكربت فعلياً على ملفيك وأنتج:
- `scripts/output/permits_import.csv` → 6169 سجل جاهز (1984–2025)
- `scripts/output/migration_report.txt` → تقرير مفصّل

**⚠️ مهم قبل الاستيراد:** التقرير يوضح أن حوالي 2142 سجل يحمل `duplicate_flag = 1`،
بسبب تداخل تغطية الملفين لنفس السنوات (2001–2009) — كل ملف رقّم إجازاته بشكل مستقل.
**راجع هذه السجلات يدوياً قبل الاستيراد النهائي** (فرز عمود duplicate_flag في Excel) لتقرر
أي مصدر هو المرجعي لكل سنة متداخلة، لأن رقم الإجازة رسمي ولا يجوز لأي برنامج تغييره تلقائياً.

خطوات الاستيراد بعد المراجعة:
1. من Supabase Dashboard → Table Editor → جدول `permits` → **Insert > Import data from CSV**.
2. ارفع `permits_import.csv` وطابق الأعمدة (نفس الأسماء تقريباً).
3. تحقق من عدد الصفوف المستوردة يطابق التقرير.

لإعادة تشغيل السكربت لاحقاً (مثلاً بعد تعديل الملفات):
```bash
cd scripts
pip install openpyxl --break-system-packages
python3 migrate_excel_to_supabase.py
```

### د) تشغيل تطبيق Flutter
```bash
flutter pub get
flutter run              # للتشغيل على جهاز/محاكي متصل
flutter run -d windows   # لتشغيل نسخة ويندوز
```

### هـ) بناء نسخ الإصدار النهائي
```bash
flutter build apk --release          # أندرويد (ملف واحد APK)
flutter build appbundle --release    # أندرويد لمتجر Play (لو احتجتموه لاحقاً رغم أن الاستخدام داخلي)
flutter build windows --release      # تطبيق ويندوز (مجلد قابل للنسخ + تشغيل مباشر)
```
ملف تشغيل ويندوز يكون في: `build/windows/x64/runner/Release/`
انسخ هذا المجلد كاملاً على أي حاسبة ويندوز — لا يحتاج تثبيت Flutter عليها.

## 3) كيف تعمل المزامنة اللحظية Offline-First

1. أي إضافة/تعديل/حذف يُكتب **فوراً** في قاعدة Hive المحلية (يعمل التطبيق حتى بدون إنترنت مطلقاً).
2. إن توفر اتصال: تُرسل العملية فوراً إلى Supabase، ويستقبلها كل الأجهزة الأخرى المتصلة
   عبر Supabase Realtime خلال أقل من ثانية، فتتحدث شاشاتهم تلقائياً + يظهر تنبيه وسط الشاشة:
   **"تم التعديل من قبل [اسم المستخدم]"**.
3. إن انقطع الاتصال أثناء العملية: تُحفظ في طابور محلي (`pending_ops_box`)، ويعيد التطبيق
   إرسالها **تلقائياً وفوراً** بمجرد رجوع الإنترنت، حتى لو كان الجهاز الآخر مغلقاً وقتها
   (سيستقبلها عند فتحه لاحقاً لأن التطبيق يسحب كل التغييرات الفائتة `fetchChangedSince` عند الإقلاع).

## 4) الأمان (يطابق ما طلبتَه)

- **تشفير الجلسة**: `flutter_secure_storage` لحفظ رمز الدخول (Keychain على iOS/macOS، Keystore على أندرويد، DPAPI على ويندوز).
- **RLS (Row Level Security)** مفعّلة على كل الجداول في Supabase: كل مستخدم يُتحقق من صلاحيته
  (نشط/أدمن) في قاعدة البيانات نفسها، وليس فقط بواجهة التطبيق.
- **الحذف الفعلي محصور بالأدمن فقط** (مطبّق بسياسة RLS منفصلة على مستوى القاعدة، ولا يمكن للموظف تجاوزها حتى بتعديل كود التطبيق).
- **سجل تدقيق كامل (Audit Log)** تلقائي بقاعدة البيانات (Trigger) يسجّل كل عملية بلا استثناء، حتى لو تم تنفيذها مباشرة من SQL Editor.
- **معايير OWASP MASVS**: البنية معدّة للامتثال (تخزين آمن، لا أسرار مكتوبة بالكود عدا anon key العلني بتصميم Supabase نفسه، اتصال HTTPS إجباري عبر Supabase SDK). لرفع المستوى للنشر عبر متجر رسمي مستقبلاً، يُنصح بإضافة SSL Pinning و Obfuscation عبر `flutter build --obfuscate --split-debug-info=./debug-info`.

## 5) نقاط مهمة يجب معرفتها

- **رقم الإجازة**: فريد ضمن كل سنة فقط (وليس عالمياً)، مطابقةً لما طلبتَه. التطبيق يتحقق من
  عدم التكرار قبل الحفظ ويعرض تنبيهاً واضحاً عند وجود تعارض.
- **رقم القطعة**: نص حر (Text) يقبل أي صيغة كما هي في بياناتك الأصلية (مثل "58قديمة" أو "92البوسعبر").
- **التاريخ**: ميلادي دائماً كما طلبتَ، بصيغة `yyyy-MM-dd`.
- **إنشاء مستخدم جديد**: لأسباب أمنية، لا يمكن إنشاء حسابات Auth من داخل تطبيق الموبايل مباشرة
  (يتطلب صلاحية Service Role الخطيرة). يُنشأ الحساب من Supabase Dashboard، ثم يضبط الأدمن
  دوره من داخل التطبيق مباشرة.
- **الخطوط العربية**: المشروع مُعد لخط Cairo — ضع ملفات الخط الثلاثة (Regular/Bold/SemiBold)
  في `assets/fonts/` (يمكن تحميلها مجاناً من Google Fonts) قبل البناء النهائي.
